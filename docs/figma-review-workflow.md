# Figma client review workflow (as set up in the Scent Pilot file)

Source: "Welcome - Start Here" page of the Scent Pilot Figma file (branded "copyrath"), read 2026-10-31.
missing info: confirm whether every 3T client file uses this same setup, and what "copyrath" refers to.

## File pages
- **Welcome - Start Here**: client instructions + Loom walkthrough.
- **CLIENT - REVIEW**: the only page clients comment on. Campaigns at the top, flows further down.
- **ARCHIVE - SENT EMAILS**: approved and sent emails, reference only.
- **INTERNAL - COPYRATH**: team working space; clients do not use it.

## Lanes on the review page
- Campaigns: Ready For Review -> Ready To Be Sent -> Queued Up / Sent Out.
- Flows: Ready For Review -> Ready To Be Set Live.

## Each email box
- "SL / PT" box above the design: subject line and preview text. Clients comment there to change wording.
- Link: only listed when a button is ambiguous (e.g. "Learn more"); obvious buttons go to the matching page.
- Design frames: R1 on the left; revisions appear to the right. Clients comment on the newest (rightmost) version.

## Approval rule
1. Client puts all comments in at once (Round 1).
2. Team revises; the new version appears to the right.
3. Round 2 is only for checking revisions.
4. Client comments exactly "Approved" on the email. **No "Approved" comment = no send.**
5. Comments after approval go through the client's channel (Slack, WhatsApp, email), not Figma.
6. New emails, offer changes and date changes go through the client's channel, not Figma comments.

## What this means for Claude
- Treat an email as approved only when the newest version has an "Approved" comment, or Danie says so.
- When building copy docs, the SL / PT pair maps to the TTM subject table.
- Figma image downloads are blocked by this cloud environment's network; inline screenshots work.
